# 晚自习带班实施计划（详细版）

> 历史方案。实施以 [2026-11-10 带班安排实施计划](2026-11-10-supervision.md) 为准。

日期：2026-10-31。状态：详细产品与实施方案，未实施业务代码。

**目标**：让教务人员通过批量选班、复用班组、批量选择时间和教师，生成可预览、可确认、可替班的带班表。

**架构**：沿用 Flutter + Riverpod + SchoolRepository + Drift。岗位需求、自动分配、日期解析、统计在领域层实现；界面与导出读取同一份生效结果。

**需求依据**：项目 PRD D13、US-006、US-032～034，以及本次对话确认的多班共一人、固定周表、自动排班和临时替班。

实施阶段按本计划任务顺序逐项交付，每个任务完成对应验收后再进入下一项。

## 1. 目标与评审结论

管理员为具体自习格配置覆盖多个班级的岗位，选择参与教师，自动生成每周固定重复的带班表；确认后进入班级、教师、学校课表，支持按日期替班、独立统计和 Excel 导出。

已确认：全自动生成、管理员自定义班组、多班共一人、选择参与教师并均衡负担、每周固定重复、首期包含临时替班。自动生成后仍须管理员预览并确认；允许修正草案。

新增确认：所有带班操作集中在“带班安排”页面；作息设置负责上课日、时间和节数，首期不增加“需要带班”的作息跳转入口。班级支持按年级/学段批量选取、取消个别班级和复用已保存班组，不要求逐班配置。

本计划给出的次数口径、生效日、教师禁排独立配置和班组快照规则，是为便于实施补齐的默认设计；与前述明确确认的选择区分记录，后续可据实际学校流程调整。

原计划方向成立，但以下缺口必须在实施前补齐：

| 缺口 | 补充决策 |
| --- | --- |
| 将晚自习时段直接等同于带班需求 | 仅具体班级格被明确设为需带班时产生需求；晚间名称只用于建议筛选 |
| 只检查给带班教师分配时是否冲突 | 正课生成、手动移动、增量协调也必须检查已确认的带班占用 |
| “均衡次数”没有计算口径 | 按岗位占用节次计算，一个岗位覆盖多个班仍只计一次；连带两节计两次 |
| 只按星期判断临时替班 | 按教学周、单双周、停课及补课映射解析实际日期 |
| 直接沿用教师授课预设作为带班禁排 | 带班单独配置禁排；授课的“一定排/不排”不自动变成带班规则 |
| 未定义配置变更和历史关系 | 固定方案按生效日期保留版本；引用失效的替班进入需修复状态 |
| 假设存在可复用的临时调代系统 | 当前未发现完整的 M5 任务树实现；首期实现带班替班及统一记录接口，不以完整 M5 为前置 |

依据：项目 PRD 的 D13、US-006、US-032～034，现有作息、排课快照、冲突检查和提交事务。PRD 尚未描述多班共岗，需同步补充；首期每岗一人，不扩展多人数岗位、楼层或场室管理。

## 2. 产品行为与规则

### 2.1 先明确班组、岗位和带班记录

| 概念 | 管什么 | 示例 |
| --- | --- | --- |
| 参与班级 | 本次准备安排哪些班级 | 初一年级全部12个班 |
| 班组 | 一名教师同时负责哪些班 | 初一1—3班 |
| 岗位 | 某班组在什么时候需要一人 | 初一1—3班，周日晚1、晚2 |
| 固定安排 | 哪位教师每周负责此岗位 | 周日晚1、晚2由张老师负责 |
| 临时替班 | 某次岗位改由谁负责 | 11月8日这两节由李老师顶替 |

班组只保存班级组合，不自带星期、时间或教师；同一个班组可应用到多个星期。岗位覆盖一组班级，每个节次只需要一名教师。

### 2.2 页面与首次使用流程

- 侧栏新增“带班安排”，使用当前学期上下文，支持按学段、年级筛选。切换筛选只改变查看范围，不改变已选择的数据。
- 首次没有方案时显示“配置带班安排”，并列出准备状态：班级已建立、作息已配置、教师已录入。缺少哪项就提供对应入口。
- 配置采用同一页面内的三个步骤：①班级与班组，②时间与岗位，③参与教师与规则。底部持续显示已选班级数、班组数、预计岗位节次数和候选教师数。
- 步骤切换保留尚未提交的输入；离开页面且有修改时提示保存配置草稿或放弃。配置草稿按学期保存在数据库，重启后可继续；求解进度和半成品不保存。
- 有方案后默认进入周表，顶部保留“常规周表 / 日期周表”切换。通过“编辑配置”进入上述步骤，不让每次查看都经过向导。
- 配置步骤只保存草稿；“确认并生效”才改变课表占用。已有有效方案时，草稿修改期间仍可查看有效周表。

### 2.3 批量选班和划分班组

班级选择器使用“学段 → 年级 → 班级”树。年级和学段均有复选框，支持全选与半选；同时提供按班级名称搜索。班级顺序沿用基础资料排序，不按名称字符串自行重排。

具体操作：

1. 勾选“初一年级”，一次选中全部班级；可以取消其中个别班。
2. 顶部显示“已选12个班”，提供“查看已选”和“清空选择”；已选班在切换年级或搜索时继续保留。
3. 在已选班级列表中，支持连续范围选择和多选，把1—3班加入一个班组，再把4—6班加入另一个班组。无需回到基础资料逐班建岗。
4. 默认名称按成员生成，例如“初一1—3班”；允许改为学校常用名称。非连续成员以摘要显示，展开可见完整清单，不能用范围名称掩盖中间未选班级。
5. 右侧列出已划分班组，左侧显示尚未分组班级；支持把班级移入其他组、移出班组、合并组、拆分组，所有操作在草稿内完成。
6. 完成后可勾选“保存班组供以后复用”。下次选取保存的班组，直接带入成员，无需重复划分。

批量选择的边界：

- “全选本年级”表示该年级全部班级；搜索结果另设明确的“选择搜索结果”，不让搜索条件悄悄改变全选含义。
- 不将“选中整个年级”自动解释为“整个年级只安排一名教师”；必须经过班组划分并展示每组人数。
- 提供“每班单独成组”和“所选班级合成一组”两个明确操作。多班共组需展示“这几个班将在同一时间由一名教师负责”的说明。
- 首期班组限同一学段；支持跨年级选班，但不允许一个班组跨学段。按学段全选时仍须在同一学段内分组。
- 本次同一批时间配置中，每个选中班级只归入一个班组；未分组班级必须明确移出本次范围后才可完成配置，不能静默漏掉。
- 保存的不同班组可以含相同班级，以适应不同日期的组合；使用时检查岗位是否在相同星期、节次重叠，重叠就指出两个岗位和具体班级。

班组复用和变更：

- 班组保存于当前学期，以稳定班级 ID 关联；班级改名后选择器显示新名称。
- 从保存班组创建岗位时复制当前成员，形成岗位成员快照。以后编辑保存班组不会静默修改已确认岗位。
- 编辑保存班组时列出引用它的岗位；可选择只更新班组，或将变更带入指定岗位的新草案。涉及有效方案时必须经过差异预览和确认。
- 删除保存班组仅移除复用入口；已存在岗位仍保留成员。删除真实班级则进入依赖变更预览，不能只删复用入口了事。

### 2.4 批量选择时间并生成岗位

- 先选班组，再选择星期和时段。星期支持多选、选择当前学段有效上课日；节次支持单选、多选和整个时段。
- 下方实时显示将创建的岗位：班组 × 星期 × 有效节次。管理员可在预览中取消不需要的整天、班组或单节。
- 仅允许选择作息中实际存在的格子，尊重上课日、每日节数覆盖和零节设置。周五无晚自习则该格禁用并说明“当日该时段为0节”；周日有晚自习则可选择。
- 对已有免任课“自习”的格子直接建立需求；其他可用空格在本页确认“设为需带班自习”后建立需求。相关标记随有效方案确认一并写入，不要求返回作息页面逐格设置。
- “不上课”格不可直接建岗，已有正课的格子拒绝建岗并定位冲突课程。预览必须列出“可创建数量”和“不可创建格子及原因”；管理员需修正或明确排除问题格子后继续，不能自动忽略。
- 同一班组在同一星期的多节安排共用岗位标识；每节保留独立成员覆盖、人员和缺口信息。首期岗位每周均出现，同时检查单周与双周课程冲突。
- 勾选“整段由同一人负责”时，同一天、同一时段的相邻节次成为不可拆分任务。不可跨星期、跨时段或跨不连续节次绑定；未勾选则逐节分配。
- 作息中的课间间隔不妨碍相邻节次绑定，但冲突判断只使用实际各节时间区间，不额外把课间算作带班占用。界面显示完整节次和起止时间。
- 提供“复制到其他星期”：仅复制班组、时段节次、连续段和候选限制，默认不复制已安排教师；重复目标先展示重复项，禁止创建两份同岗需求。
- 有效岗位覆盖格禁止排正课，即使该岗位缺教师。删除岗位时默认保留已有自习标记，可明确选择同时撤销；只允许撤销由本功能创建且已无其他引用的标记，不删除原有免任课设置。

### 2.5 参与教师与规则配置

- 教师列表来自当前学期，支持姓名搜索、教师分组筛选和批量勾选；选中教师组表示选入当前成员快照，之后教师组变化不自动改变有效候选池。
- 方案教师池默认为空，管理员必须明确选择；支持“全选当前结果”。班组与教师任课关系不绑定，教师无需是所带班级的任课教师。
- 默认所有岗位使用方案教师池。岗位设置提供“限制候选教师”，只能从方案池缩小范围；空限制表示继承，明确选空则提示该岗位无人可选。
- 每位教师可配置每周带班节次数上限和天数上限，支持批量设置再单独修改。空白不限，节次数上限0表示不参与；天数允许0—7，次数只接受非负整数。
- “带班禁排”在本页教师规则中设置，支持多个星期和时间格批量标记。首期不用授课的“一定排/不排”推导教师能否带班；授课的实际占用仍必须检查。
- 教师规则表中展示“参与岗位数、带班禁排、每周最多节次、每周最多天数”。生成后在预览中展示每人调整前后节次数，无需另加独立教师负担卡片。
- 教师池或规则变化只影响草稿；已确认人员退出候选池时，新草案必须换人或留缺口，不能静默保留一条不合法安排。

#### 教师与岗位的匹配偏好：任教班级、本年级、指定学科

需求：在不产生时间冲突、不过硬上限且尽量填满岗位的前提下，尽量把教师安排到熟悉的班级、年级或擅长的学科。三项可分别开启并排序，不要求教师默认同时满足三项。

| 条件 | 数据来源与判定 | 多班岗位的处理 |
| --- | --- | --- |
| 任教班级优先 | 当前学期 lessonCount > 0 的 TeacherAssignment 中，该教师实际任教的班级 | 展示“任教本组2/3个班”；按匹配班数/岗位班数评分，不把只教其中一个班说成全组任课教师 |
| 本年级优先 | 由当前学期有效任课班级推导教师任教年级，无需再录一份教师所属年级 | 按岗位中处于该教师任教年级的班级数/岗位班数评分；跨年级教师可同时匹配多个年级 |
| 指定学科优先 | 岗位明确选定目标学科；教师当前学期任教学科或 Teacher.subjectIds 标签命中任一目标学科 | 每个岗位节次可选目标学科，例如周一晚1数学、晚2英语；无目标学科则该项不参与评分 |

- “本学科”必须先明确相对于什么学科。普通看班没有天然学科，默认不启用学科偏好；学科辅导岗位可选数学、语文等作为目标。教师科目标签只作为匹配依据，不被解释成资格认证。
- 任课关系取本学期已保存的任课份额，不依赖自动排课是否完成；任课只有单周或双周也可建立熟悉关系，真实可用性仍按发生周次另行检查。
- 教师无任课资料时不推测其年级或班级关系，显示“暂无任课关系”；可以通过已有学科标签匹配学科。资料补全后重新生成草案，不自动修改已确认带班表。

配置交互：

1. 方案“人员匹配”区域显示三个可勾选项及上下排序按钮，默认开启“任教班级优先 → 本年级优先”，学科项在设置目标学科后可开启。
2. 岗位默认继承方案偏好；可单独调整，例如数学辅导岗位选择“指定学科 → 任教班级 → 本年级”。覆盖必须有明确标识，可恢复继承。
3. 普通模式为“优先满足”：当匹配教师因授课、带班、禁排或上限不可用时，允许从已选教师池中安排其他合法教师，并标记未满足的偏好。
4. 有明确业务要求时，可将条件加入“必须符合”。启用多项必须条件时选择“满足任一项”或“满足全部”，默认任一项；任教班级与年级的必须命中均要求覆盖岗位全部班级。未满足的教师被排除，缺人时留缺口，绝不自动放宽必须条件。
5. 手动换人和临时替班面板也展示相同匹配标签。软偏好不阻止临时救急；“必须符合”作为岗位资格要求继续检查。班组和学科要求变化时，现有锁定及替班记录都需重新校验。

排序和均衡：

- 方案选择“匹配优先”或“均衡优先”，默认匹配优先，符合本次尽量满足关系条件的需求。
- 匹配优先：硬规则 → 覆盖岗位节次数 → 按所选顺序比较匹配得分 → 均衡带班节次数 → 集中带班天数。
- 均衡优先：硬规则 → 覆盖岗位节次数 → 均衡带班节次数 → 按所选顺序比较匹配得分 → 集中带班天数。
- 每项关系分归一到0—1，按分配的岗位节次数汇总；班级/年级用上述覆盖比例，学科命中记1。三项不简单累加为一个大分数，而是按所选先后逐项比较，避免多项次要命中盖过主偏好。
- 岗位覆盖自定义偏好顺序时，把该岗位的第1/2/3优先项分别归入全局第1/2/3得分槽；未开启项贡献0。相同输入、规则与种子应可复现。
- 次数和天数硬上限始终有效。匹配优先可能让本班教师承担更多带班，预览需同时展示每人次数和匹配率，不能宣传两项目标总能同时最优。

结果解释：

- 教师格可展开显示“任教本组2/3班”“本年级”“数学教师”；同时展示为什么选择此人。
- 未满足优先条件时显示“已由其他教师补位”；展开列出高匹配候选实际被排除的原因，例如“本班任课教师张老师此时有课、李老师已达每周上限”。
- 统计按“岗位节次”给出任教班级覆盖率、同年级覆盖率、学科匹配率及未满足偏好数量；不把多班岗位重复计入教师次数。跨班覆盖率使用班级数为分母时必须另注明口径。
- 教师池中没有匹配人员时建议调整教师池或偏好；系统不自行将未选择的教师加入固定排班。

例：初一1—3班的数学辅导岗位，王老师教本组1、2班数学，李老师教初一其他班数学，赵老师教初二数学。在三人都合法可用时，默认更倾向王老师；王老师有课时倾向李老师；两人均不可用时，软偏好允许赵老师补位并说明原因。若“必须本年级”，赵老师不能补位，该岗位进入缺口清单。

### 2.6 自动排班

- 硬规则：教师在候选池内；岗位和班级无重复覆盖；与该教师正课、其他带班不冲突；遵守带班禁排、已锁定人员、每周次数上限及每周天数上限。上限空白表示不限，次数上限 0 表示不参与。
- 跨学段按起止时钟判断重叠，时间区间首尾相接不算冲突。存在跨学段资源比较却缺少时钟信息时，报告待补全时间，不能判定为“空闲”。
- 带班禁排使用个人配置，按实际星期与时间占用检查；课程预设仍由课程求解器解释。教师授课导致的实际占用无论来自哪个班级或学段都必须检查。
- 求解优先级依次为：满足硬规则、尽量填满岗位，再依据人员匹配设置比较关系匹配和负担均衡，最后尽量集中带班天数；未启用关系偏好时回到均衡优先。均衡以参与教师周带班节次数的平方和为评分；不把带班并入正课课时工作量。
- 先处理候选人少的任务，配合回溯或局部重排，避免单次贪心造成可避免缺口。保存算法版本、种子及输入指纹，相同输入和种子可复现；结果不宣称数学最优。
- 默认重新生成未锁定部分，保留已锁定安排；锁定与硬规则冲突时阻止提交并定位问题。“全部重排”先在草案中展示被替换安排。
- 缺口逐项显示岗位、班级、时间、缺少人数及实际阻断原因；超时须区分“搜索未完成”和“已找到方案”，不能把未找到直接解释为无解。
- 草案可换人、清空、锁定、恢复至已确认版本；每次修正执行同一套校验。只要有硬冲突就不能提交；存在缺口但无硬冲突时，允许明确确认“保存含缺口方案”，持续显示缺口，不标为全部完成。

生成与修正的具体交互：

1. 点击“生成带班表”前显示本次参与班级、岗位节次数、候选教师和生效日期摘要；先执行数据完整性校验，再启动后台求解。
2. 生成中显示已用时间、当前已覆盖/总节次数和“取消”；不能重复启动，也不冻结整个应用。取消后仍保留原有效周表及配置草稿。
3. 结果出现后展示草案周表；变更格显示“原教师 → 新教师”，未分配位置显示“缺1人”，点击可查看候选被排除的原因。
4. 点击教师格可换人；候选列表逐项显示可用或不可用及原因。选择合法教师后实时更新缺口、节次数、天数和与有效方案的差异。
5. 选择“此人此处不排”会记录带班禁排并从该位置释放教师；“清空”只移除本次人员，不新增禁排。“锁定”使后续自动生成保留该合法安排。
6. 常规“重新生成”保留锁定项，重排未锁定项；“全部重排”需明确包含解除锁定，并先在草案中展示变化。
7. 点击“确认并生效”进入最终差异摘要；有缺岗时按钮改为“确认保存，仍有X处缺岗”，不能用相同成功提示掩盖缺口。

### 2.7 固定方案、确认和版本

- 草案与有效方案分离；生成或取消草案不改变有效课表。首次方案默认今天生效；如学期尚未开始则取第一个教学日。替换方案默认下一教学周周一生效，可选学期内不早于今天的日期。
- 有效方案按生效区间版本化；同一学期任一日期只能有一个有效版本。新版本只替换生效日及其后的安排，历史日期仍按旧版本查询。
- 预览同时展示人员变化、次数变化、缺口，以及受影响的替班。提交时在事务内重新读取并校验输入指纹和有效版本号，陈旧草案要求重新预览。
- 指纹覆盖岗位、参与教师、带班规则、匹配偏好顺序与必须条件、目标学科、教师科目标签与任课关系、教师/班级状态、作息和时钟、正课安排及相关日历；不能仅复用只包含原有排课输入的指纹。
- 修改依赖设置后保留旧课表可见，受影响范围进入只读待协调状态；显示“变更前 → 变更后”，确认后才更新有效安排。未受影响范围不额外冻结。
- 新增岗位与既有正课冲突时要求管理员先解决冲突；以后正课重排、拖放、增量协调和带班修改均执行双向占用检查。
- 删除班级、教师、时段或节次前预览受影响岗位与未来替班。当前及未来非法安排进入待协调，不把替班静默套到别的岗位；历史记录保留当时名称与时间摘要。

- 无教学日历时允许确认仅用于周模板的版本，界面标为“日期待配置”；该版本不声称已按具体日期生效。配置日历后需重新预览生效日与已有替班依赖，再启用日期功能。
- 新增版本默认取代指定生效日及之后的已安排版本；预览列出被替换的未来版本，确认后才结束其有效区间。相同生效日的重复提交以版本号拒绝，不生成两份有效安排。
- 查看过去日期时固定使用当日版本、成员与名称快照；当前基础资料改名不能篡改历史导出中的既定记录摘要。
- 草稿遇到外部数据更新后保留输入并标为“需要刷新预览”；展示变化来源，由重新校验生成新预览，不直接抛弃管理员的分组工作。

### 2.8 日期周表与临时替班

- 同一工作区提供“常规周表”和按教学周切换的日期周表，复用相同岗位网格。常规周表配置固定安排；日期周表查看当周生效人员并发起替班。
- 解析顺序：学期与教学周 → 当日停课/补课映射 → 当日生效固定方案及其作息星期 → 该自然日的有效替班。补课采用源课表星期及源周次检查课程；映射不完整则提示修复，不能自行猜测。
- 未配置教学日历可编辑固定周模板，但禁用日期替班和按日期统计，提供“配置学期日历”入口。学期范围依据教学周锚点与周数推导，不另造学期起止字段。
- 首期遵循当前 CalendarException 的学期级范围；不在本功能内顺带扩展学段级日历例外。停课当天不展开带班；补课当天跟随所采用的作息日。
- 从日期周表选择一个岗位的单节或连续节次替班，显示原教师、替班教师、覆盖班级、实际日期和时间、备注。候选教师来自本学期教师，可选教师池之外人员；仍须通过冲突与带班禁排检查。
- 一次替班覆盖所选岗位的全部班级；同一日期、同一岗位节次只允许一条有效覆盖。再次换人以替换操作原子取消旧记录并新增记录，避免覆盖链。
- 取消替班恢复当日当前有效的固定安排；提交取消前也检查恢复结果，若会产生冲突则说明阻断原因，待调整相关安排后取消。历史记录不删除。
- 固定方案、日历或岗位变更导致替班失效时保留记录并标为“需修复”，不悄悄丢弃或重新挂接；相关日期不得以完整有效课表对外导出。

- 日期周表的列头显示星期与自然日期，行显示班组和晚自习节次。选择周日返校日时仍在同一周表操作，不另建独立日期列表。
- 跨日补课仍使用实际自然日保存替班；课表星期只决定采用哪份岗位，不代替替班记录的日期键。
- 临时替班不受原方案候选池限制，但须展示“本次临时加入”；覆盖后不得与该教师当日其他已生效安排冲突。模板次数/天数上限用于固定排班，临时替班超出模板上限只提示增量，不作为硬拒绝；带班禁排和真实冲突仍硬性阻止。
- 所选岗位原本缺教师时操作名为“补齐本次带班”，原教师为空；仅补齐该日期，不自动填满后续每周岗位，统计单列本次新增。
- 替班对话框先校验覆盖范围、候选和时间，确认时再次在数据库事务中校验。再次换人和取消都保留操作时间与原因，按操作顺序可查。

### 2.9 展示、统计、导入导出

- 岗位周表显示覆盖班级和人员；班级课表显示活动与带班教师；教师课表显示活动与所带班组；学校课表按班级展开。同一多班岗位在教师侧只出现一次。
- 周模板统计为“周计划带班节次数”；日期范围统计列出基准计划、替班增减和调整后计划。连带两节计两次、带三个班的一节计一次；另列带班天数。明确数据来自安排计划，不代表考勤。
- 统计独立于正课工作量；公平评分、预览、界面、导出使用同一计数函数。临时替班不回改固定周表的均衡结果或每周模板配额。
- 替班记录支持日期、教师、岗位、有效/已取消/需修复状态筛选；未来对接调代课时复用统一记录协议，不预先实现完整任务树。
- Excel 导出包含固定值班表、所选日期周表、独立统计及替班明细；共用现有课表样式选项，并标明日期范围、模板/日期口径和缺口。带缺口的合法方案可导出，但必须明显标记缺岗。
- 按 US-032 提供需求 Excel 导入：岗位、班级组、星期、时段及节次为主要列；先解析和预览，再校验归属、重复覆盖和教学状态，整批确认写入。无法唯一匹配的班级、时段或教师拒绝导入并指出行号。

- 统计中同一教师同一天多个岗位只计一个带班日；单节替班一节只影响一节，连续段替班两节影响两节。取消后从当前统计恢复，但记录仍保留。
- 日期统计遇到需修复数据时展示受影响日期和未计入数量，不提供声称完整的结算统计导出；可导出明确标记状态的诊断清单。
- 导入模板每行表示“班组 + 星期 + 时段 + 一个节次”，班级组成员放在单独的“班组成员”表，每行一个班级，避免用中文逗号拆班名。使用导出模板中的标识优先匹配；外部文件无标识时使用学段/年级/完整名称匹配，不允许同名误归属。
- 一次导入只创建或更新配置草稿，不能直接变更已确认人员或生效版本；最终仍走自动分配及确认流程。预览标明新增、更新、重复和错误行；存在错误不提交。

### 2.10 完整操作示例

场景：初一12个班，每3个班由一人带班，周一至周四和周日晚自习两节；周五、周六不安排。

| 步骤 | 管理员操作 | 界面结果 |
| --- | --- | --- |
| 1 | 在班级树勾选初一年级 | 一次选中12个班 |
| 2 | 把1—3、4—6、7—9、10—12班分别建组 | 显示4个班组，每组3班，并保存供复用 |
| 3 | 选周一、二、三、四、日，选晚1与晚2 | 预览4组×5天×2节＝40个岗位节次 |
| 4 | 勾选整段由同一人负责 | 每组每天形成1个两节任务，共20个任务 |
| 5 | 选10名教师，按需设禁排和上限 | 参与池和阻断条件清楚可见 |
| 6 | 点击生成 | 无额外限制且可以均分时，每人4节；同一时刻至少需4人 |
| 7 | 检查差异和缺岗，确认生效 | 班级、教师、学校课表同步展示 |
| 8 | 某周日张老师请假，选其两节岗位替班 | 该日改为李老师，其他星期和后续周保持原安排 |

下一次增加初二：切换年级批量选班，划分并保存初二班组，选择时间和参与教师后重新生成草案。对初一已锁定的合法安排予以保留；两个年级共用教师时统一检查真实时间冲突。

## 3. 技术落点与实施顺序

沿用 Flutter、Riverpod、SchoolRepository 和 Drift；领域模型与求解器不依赖 Flutter 或数据库。Widget 不直接操作表。新增带班功能目录，不顺带重构现有页面。

最小接口契约：

| 类型/操作 | 职责 |
| --- | --- |
| SupervisionClassGroup | 可复用班组名称、学期、学段、稳定班级成员 |
| SupervisionPost | 稳定岗位标识、学期、覆盖班级、作息位置、连续段、候选教师和逐节目标学科 |
| SupervisionTeacherRule | 教师候选资格、带班禁排、可空次数/天数上限 |
| SupervisionMatchingPolicy / MatchResult | 有序偏好、必须条件及任一/全部组合、匹配/均衡优先模式；输出班级/年级覆盖、学科命中和解释 |
| SupervisionPlanVersion / Assignment | 有效区间版本与每岗位节次人员，可空人员表示缺口 |
| SupervisionSubstitution | 自然日、岗位节次、方案引用、原/替班教师摘要、状态与原因 |
| SupervisionSnapshot / Preview | 不可变求解输入、指纹、草案、缺口、阻断和次数差异 |
| EffectiveSupervisionResolver | 日期解析、占用和统计的共同来源，课表与导出复用 |
| 仓储操作 | 读取快照、预览配置/求解、按期望指纹和版本事务提交、创建/替换/取消替班 |

### 3.1 数据与状态约定

| 数据 | 关键内容与约束 |
| --- | --- |
| 班组及成员 | 学期、学段、名称、班级ID；同组成员去重，跨学段成员拒绝保存 |
| 配置草稿 | 学期、班组成员快照、岗位、教师池、规则、连续绑定和修改时间；同学期保留一份当前编辑草稿 |
| 固定方案版本 | 版本ID、生效日/结束日、修订号、来源指纹、算法版本、种子、创建时间、状态；有效区间不重叠 |
| 岗位与节次 | 稳定岗位ID、班级快照、星期、学段作息格、连续任务ID、候选限制；依赖变更时可对齐同一岗位 |
| 节次分配 | 方案版本、岗位、节次、教师ID或缺口、锁定状态；同版本同岗位同节次唯一 |
| 替班及事件 | 自然日、岗位和版本引用、节次集合、原/替班教师摘要、状态、原因、创建/取消时间；同日期同岗位节次只有一条有效覆盖 |
| 历史摘要 | 已确认时的班组成员名称、教师名称、活动名称和时间；基础资料删除不级联抹掉历史摘要 |

- 结构化查询和唯一约束落到 Drift 表；已确认版本的快照用于重建和审计，不让 UI 自行拼接存储 JSON。历史摘要和可删除的当前资料引用分开处理。
- 草稿状态为“可编辑/需要刷新”；求解状态为“未开始/生成中/已生成/已取消/失败”；有效版本显示“完整/有缺口/待协调”。状态分别表达，避免用一个成功标志覆盖全部问题。
- 所有可确认修改在事务中重验并写入；配置草稿不会进入有效课表查询。求解器返回结果只保存在内存，显式保存的完整草案才可进入草稿存储。
- 日期周表、临时替班、课表展示、占用检查、统计与 Excel 共用 EffectiveSupervisionResolver；不得各自重复推导谁在某天带班。
- 查询固定周模板时使用当前选定版本；查询自然日期时先确定当日版本。历史名称和时钟来自版本摘要；教学日历后续修订引起日期统计变化时须重新预览，不能将计划数据称作考勤。
- 班级、教师、方案版本均使用稳定ID；显示名称和列表顺序不作为关联键。岗位重命名不改变ID；复制为新岗位必须分配新ID。

### 3.2 仓储与 Provider 的分工

- 复用现有 classesForTermProvider、routinesForTermProvider、freeSlotsForTermProvider、teachersProvider、teacherGroupsProvider 及其 SchoolRepository 数据源，避免在新页面为每个班级分别发起查询。
- 新增班组流、配置草稿流、方案版本流、指定周生效周表和替班记录流；流参数均含学期，日期查询使用归一化自然日。
- 新增带班控制器负责步骤输入、批量选择、草稿保存、后台求解、预览提交及错误提示；控制器通过 SchoolRepository 访问数据。
- 领域层提供配置校验、候选生成、关系匹配、带班求解、分配校验、日期解析和计数函数。关系匹配由任课和科目标签预建索引，界面、求解和统计共用 MatchResult。正课与带班共享底层时间占用判断，保留各自的课程/带班业务约束。
- 仓储提供“保存复用班组、保存配置草稿、加载求解快照、生成提交预览、提交方案、创建或替换替班、取消替班”操作。提交必须携带期望输入指纹和期望版本号；错误至少区分陈旧输入、规则阻断、资料失效和存储失败。
- 预览结果包含按岗位的人员前后差异、每人节次/天数变化、缺口、受影响版本与替班清单；前端只负责展示，不自行计算另一套结果。

### 3.3 实施任务与交付点

每项任务先编写行为测试并观察预期失败，再实现必要行为、运行对应验证并检查差异。独立提交由实施时的仓库工作流决定；不得夹带现有无关文件。

## 4. 验收与验证

- **批量选班**：年级全选和半选、学段全选、取消个别班级、搜索结果选择与年级全选含义独立、切换筛选保留已选、连续选择、班级按基础资料顺序展示。
- **班组**：12班组成4组、每班单独成组、选中班级合组、移组与拆合、未分组提示、跨学段拒绝、重复覆盖检测；复用后编辑原班组不改变已确认岗位，批量应用变更必须进入草案。
- **批量操作与恢复**：多天、多节创建数量准确；复制到已有目标不产生重复；错误格不能静默跳过；离开提示与配置草稿重启恢复正常。
- **岗位**：周五零晚自习、周日有效；同班重复覆盖；自习与正课交错；一个岗位带多个班；整段任务不被拆分；删除岗位可选择保留自习标记。
- **求解**：候选池为空、次数上限 0、周天数上限、带班禁排、单/双周正课、跨学段时间重叠及缺时钟、锁定冲突；构造贪心失败但重排可完成的例子；同种子可复现；超时与取消不写库。
- **公平性**：多班不重复计数，两节连续计两次；在无额外约束且岗位可均分的样例中次数差不超过一；有限制时优先合法与覆盖率，不承诺人人完全相等。
- **关系匹配**：任教本组全部/部分班、同年级其他班、跨年级任课、无任课关系、学科标签与实际任教学科、未设置目标学科；验证软偏好可补位，必须条件的任一/全部不被绕过，岗位覆盖策略及顺序生效，匹配/均衡两模式确有区别，任课变化使旧预览失效，未命中时解释来源准确。
- **双向保护**：先排正课再建带班、先有带班再生成/移动正课、修改作息再协调，均不能形成未提示的重叠或覆盖已有已确认课表。
- **提交**：真实数据库执行保存 → 预览 → 确认；陈旧指纹、版本变化、事务中断全部拒绝或回滚；有缺口需明确确认；无语义变更不生成待协调；历史版本仍可查询。
- **日期与替班**：停课、补课采用其他星期及源周次、未配日历、学期边界、重复替班、部分连续节次替班、取消恢复冲突、源岗位/版本失效和需修复记录。
- **展示与交付**：岗位、班级、教师、学校课表及 Excel 一致，多班教师侧不重复；统计区分模板与日期；带缺口导出有标记；需修复日期阻止误导性交付；导入错误定位到行且不部分落库。
- **兼容**：旧数据库升级不丢原课表；新旧排课快照兼容；备份恢复含带班与历史；学期复制重新映射且不带入旧替班；旧数据无带班时行为保持兼容。
- 实施阶段运行领域与仓储定向测试、关键 Widget 测试、flutter analyze、macOS debug 构建及全套测试；按需使用 --no-pub。定向结果与全量结果分别报告；本次评审未运行这些检查，历史失败记录不能替代当前基线。

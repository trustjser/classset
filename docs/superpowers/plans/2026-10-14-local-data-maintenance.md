# 课集本地资料维护闭环 Implementation Plan

> **For agentic workers:** This plan is executed inline in the current task. The user asked for the implementation directly.

**Goal:** Build a runnable Flutter desktop app that stores and edits terms, stages, grades, classes, and per-day schedules in a local SQLite file.

**Architecture:** Follow the confirmed architecture with Flutter, Riverpod, Drift, and SQLite. Domain models describe terms and stage routines; a Drift database and repository own persistence; Riverpod exposes data to focused term, class/stage, and schedule screens.

**Tech Stack:** Flutter desktop, Dart 3, Riverpod, Drift, SQLite, path_provider.

**Spec:** `docs/PRD.md` (US-001–003, US-038–040); `wiki-doc/architecture/keji/【ARCH】课集P0-前端架构设计.md` (sections 2.1–2.4); Ardot design `https://ardot.tencent.com/file/735702770970447`.

## Global Constraints

- Store all business data locally in one SQLite database; do not add network services or telemetry.
- A term owns its stages; each grade belongs to exactly one stage; classes belong to exactly one grade.
- Each stage stores its own seven-day teaching-day selection, lesson-period defaults, day overrides, and lesson times.
- Day overrides accept 0–9 and override the period default for that weekday only.
- UI and persistence remain separated through repositories and Riverpod providers.
- Keep the deliverable limited to term, stage, grade/class, and daily routine maintenance.

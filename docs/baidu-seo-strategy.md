# 课集 ClassSet 百度 SEO 优化策略

> 编制：百度 SEO 专家｜日期：2026-11-10｜审计对象：本仓库 `website/`（线上 `https://classset.app/`，Cloudflare Pages 静态站）
> 本文只做诊断与策略，**未修改官网任何文件**。所有实施动作均列出，待确认后执行。

---

## 0. 结论先行

**这不是「排名不佳」，而是「百度基本没收录 + 品牌词零占位」。** 先解决收录，再谈排名。

| 实测（2026-11-10，百度网页搜索） | 结果 |
| --- | --- |
| `site:classset.app` | 「抱歉，未找到相关结果」→ 疑似零收录 |
| `课集 ClassSet 排课软件` | 前排为「Class 课程表 App」下载站、CSDN、91 单机等，**官网未出现** |
| `排课软件` | 百度百科 + AI 生成答案置顶，推荐二一排课、排课大师、快排课、极课排课、爱排课/课表易、兴文排课、校宝排课，**无课集** |
| 品牌词泛检索 | 「ClassSet」已有一款同名 iOS 应用（团课歌单大脑），品牌词被占用 |

**三个根因（按优先级）**

1. **合规与地基**：`.app` 域名 + Cloudflare Pages（本次探测落在 AMS 海外节点），未见 ICP 备案号与大陆主机保障；百度 Sitemap 提交能力、大陆访问速度、企业实体可信度都受影响。
2. **抓取障碍**：`/robots.txt`、`/sitemap.xml` 都返回 `200 text/html` 的首页内容；正文默认 `opacity:0`、依赖 JS 才显现。百度蜘蛛对 JS 渲染支持弱，可能抓到「隐藏/空」页面。
3. **内容与结构**：全站只有 **1 个可收录 URL**，导航全是 `#` 锚点；无帮助中心、无原创内容矩阵、无主体/联系方式/隐私页；竞品靠大量中文文档覆盖长尾词。

**策略主线**：`P0 补合规与抓取地基 → P1 把单页站扩成中文内容矩阵 → P2 抢百度生态与 AI 答案引用`。

> 预期节奏：技术修复与主动推送可在数周内改善收录；新站稳定进入核心词前 10 通常需 3–6 个月（行业经验，非承诺）。

> 备案不是收录的绝对开关（海外站也可能被收录），但它是这个站最值得优先解决的结构性瓶颈：**决定大陆速度、Sitemap 提交资格、以及 AI 答案是否愿意引用你**。据第三方 2026 指南，百度站长平台 Sitemap 提交仅向已完成 ICP 备案的站点开放；未备案站点仍可用手动提交、API 推送、自动推送 JS。

### 2.2 技术 SEO

| 问题 | 证据 | 影响 | 修复 |
| --- | --- | --- | --- |
| **robots.txt 返回首页** | `/robots.txt` → `HTTP/2 200`、`content-type: text/html`，正文为首页 | 百度读不到爬虫协议，抓取规则不可控 | 在 `website/` 根目录放真实 `robots.txt` |
| **sitemap.xml 返回首页** | `/sitemap.xml` → 同样 `200 text/html` | 无法向百度批量提交页面；属软 404 | 放真实 `sitemap.xml`；Pages 有真实文件即按文件返回，不再 fallback |
| **正文默认不可见** | `.reveal { opacity:0; transform:translateY(16px) }`，靠 `main.js` 的 IntersectionObserver 加 `is-visible` | 百度蜘蛛不执行 JS 时可能判定内容隐藏/空白，甚至触发隐藏文本风险 | 改渐进增强：默认可见，仅 JS 可用时才启用入场动画 |
| 只有 1 个可收录 URL | 导航全为 `#features` / `#why` / `#workflow` / `#download` 锚点 | 一个页面最多争 1–2 个词，长尾词无落地页 | 多页化（见 §6） |
| 无结构化数据 | 无 JSON-LD | 富摘要、AI 答案引用机会丢失 | 加 `SoftwareApplication` / `FAQPage` / `BreadcrumbList` |
| 无主动推送 | 无 API 推送 / 自动推送 JS | 新页面等蜘蛛自然发现，新站很慢 | 接 API 推送 + 自动推送代码 |
| TDK 待优化 | title 约 22 字（可）；description 约 100 字（百度建议 ≤78 汉字）；`meta keywords` 已有但权重有限 | 摘要被截断、核心词位置偏后 | 按 §5 重写 |
| 已做对的部分 | `lang="zh-CN"`、viewport、单一 H1、静态 HTML 正文、`canonical`、OG、响应式、HTTPS、无被墙资源 | 基础不差，别推倒重来 | 保持 |

| 问题 | 证据 | 风险 |

## 5. 可直接复制的修复清单（P1）

### 5.1 `website/robots.txt`（新建）

```text
User-agent: Baiduspider
Allow: /

User-agent: *
Allow: /

Sitemap: https://classset.app/sitemap.xml
```

### 5.2 `website/sitemap.xml`（新建，多页化后按实际 URL 更新）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://classset.app/</loc>
    <lastmod>2026-11-10</lastmod>
    <changefreq>weekly</changefreq>
    <priority>1.0</priority>
  </url>
</urlset>
```

> Cloudflare Pages 会把不存在的路径回退到 `index.html`；**补上真实文件后**才会返回正确 `content-type`。上线后用 `curl -I` 复核：应为 `200` 且 `content-type: text/plain` / `application/xml`。

### 5.3 修复 `.reveal` 隐藏正文（`styles.css`）

```css
/* 默认可见，保证无 JS 环境（含搜索引擎蜘蛛）能读到完整正文 */
.reveal { opacity: 1; transform: none; }

/* 仅在 JS 确认可用时启用入场动画：在 <head> 加 document.documentElement.classList.add('js') */
html.js .reveal { opacity: 0; transform: translateY(16px); transition: opacity .6s ease, transform .6s ease; }
html.js .reveal.is-visible { opacity: 1; transform: none; }
```

同时把 `@media (prefers-reduced-motion: reduce)` 中的 `.reveal` 规则改为 `html.js .reveal { opacity: 1; transform: none; transition: none; }`，保证选择器权重能覆盖初始隐藏。

## 6. 内容矩阵与站点结构

| 目录 | 页面数 | 目标词类型 | 更新频率 |
| --- | --- | --- | --- |
| `/` | 1 | 核心词 + 品牌词 | 月 |
| `/features/<功能>/` | 6–8 | 场景长尾（单双周、合班、免任课、晚自习、跨学段、导出打印…） | 随版本 |
| `/guide/` | 15–20 | 操作问答（对标水晶排课 17 篇指南、51 排课帮助中心） | 每周 2–3 篇 |
| `/faq/` | 8–12 | 选型问答 + `FAQPage` 结构化数据 | 双周 |
| `/compare/` | 2–3 | 客观对比（本地 vs 云端、仅 Windows vs 跨平台） | 季度 |
| `/download/`、`/changelog/` | 2+ | 品牌 + 下载词，提供持续更新信号 | 每次发版 |
| `/about/`、`/privacy/` | 2 | 信任页 | 半年 |

**写作规范（同时服务百度蓝链与 AI 答案引用）**

1. 答案前置：开头两行直接给结论，后文展开；一个 H2 回答一个具体问题。
2. 结构化：步骤用有序列表，对比用表格，参数用表格，避免长段无标题文字。
3. 原创深度：≥800 字，含产品真实截图/字段级说明，禁止采集改写（飓风算法）。
4. 可信度：标注发布日期、更新日期、作者/团队；引用可核验事实，不用「最好/第一」等绝对化用语。
5. 内链：首页 → 栏目 → 文章 ≤3 层，锚文本描述性；每篇文章回链对应功能页。
6. URL：小写、连字符、静态路径，不带参数；全站统一主域并 301。

## 9. 风险与依赖

1. **`.app` 备案风险**：多家接入商资料把 `.app` 列为未获工信部批复/多数渠道不可备案的后缀（也有资料称部分渠道可过审），**必须以接入商检测结果为准**。若不可备案，建议注册 `.cn` / `.com.cn` 作为中文主域，将 `classset.app` 做 301 跳转、全量更新 canonical 与 sitemap，避免双域重复收录分散权重。换域成本：品牌一致性、站长平台重新验证、已有链接权重。
2. **不备案的替代路径**：仍可手动提交 / API 推送 / 自动推送 JS，但 Sitemap 提交资格受限，且大陆访问速度与「企业实体可信度」信号偏弱，长期天花板明显。
3. **内容合规**：对比页不得贬损竞品；避免绝对化用语；邮箱收集需隐私政策（个人信息保护法）。
4. **产品状态**：官网「免费下载」与「即将发布」并存，属最高优先级的文案修正项；同时表单需接后端才能衡量 SEO 转化。
5. **范围控制**：本次仅交付策略文档，未改动 `website/` 下任何文件，也未新增页面。

## 10. 需要你确认的 6 件事

| # | 问题 | 为什么关键 |
| --- | --- | --- |
| 1 | 优化对象是否只有 `classset.app`？是否还有 `cn.yipaike`（课易排）站点？ | 双站需分别制定策略，避免同主体内容重复导致收录分散 |
| 2 | 是否有大陆可备案主体？`.app` 是否在接入商检测过可备案？ | 决定是否需要换域名、能否用大陆主机与 Sitemap 提交 |
| 3 | 百度搜索资源平台 / 百度统计账号是否已注册？能否提供当前收录与流量基线？ | 决定 KPI 起点与「零收录」判断的最终确认 |
| 4 | 是否允许把官网从单页扩成多页内容站（`/guide/`、`/faq/`、`/compare/` 等）？ | 长尾词与 AI 引用的必要条件 |

| 6 | 是否要我直接执行 P1 技术修复（robots/sitemap、reveal、TDK、结构化数据、统计与推送）？ | P1 不依赖备案，可立即见效 |

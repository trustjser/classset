## 一、背景与目标

### 1.1 问题描述

中小学教务/排课人员当前使用的代表性工具（水晶排课）存在以下具体问题：

1. **仅支持 Windows**（PE32 x86 + Delphi/VCL + Jet OLE DB），macOS / Linux 用户无法使用，也不适配 Apple Silicon 等新硬件。
2. **跨产品交换有限**：数据文件（`.dat/.yqd/.backyqd`）使用原软件专有格式；官网提供部分 Excel 导入/导出和 `.yqd` 备份恢复，但不同产品之间仍需按其表格格式转换。[官方总览](https://www.myzan.cn/help/index.html)、[反导入说明](https://www.myzan.cn/help/11.html)。
3. **界面与技术栈老化**：本次样本有 67 个窗体、1942 个组件的传统桌面 UI；部分导出路径涉及本机 Office/WPS 自动化。高分辨率适配的完整实测情况尚未核验。
4. **本次分析未见跨学段与单双周的完整支持**：当前样本的界面、已跟踪求解入口及公开操作说明没有给出两种能力的完整操作流程和冲突规则。新产品将明确支持九年一贯制学校的不同作息与跨学段教师，以及单双周课表；这里不以证据缺失断言原软件所有版本绝无此能力。
5. **收费且闭源**，学校无法自行定制。

教务老师现在的将就方式：在非 Windows 电脑上装虚拟机跑排课软件，或用 Excel 手工排课（易冲突、难统计）。

### 1.2 产品定位

做一个**功能对标并超越水晶排课**的跨平台桌面排课软件：覆盖「基础资料 → 约束设置 → 自动排课 → 课表编辑 → 调代课/统计 → 导入导出打印」全流程；原生支持**多学段（九年一贯制等）**、**单双周**、**按天差异作息与晚自习**；单机离线可用，本地数据文件自包含，一次性买断。

### 1.3 目标

| # | 目标 | 衡量指标 |
|---|---|---|
| G1 | 核心排课闭环达到可替代水平 | 第 1 个正式版本覆盖本文全部 P0 需求；P1 需求在 2 个版本内补齐。这里的“可替代”仅指 P0 定义的录入、排课、手工调整、备份和交付场景，不指原软件全部功能（如监考） |
| G2 | 跨平台体验一致 | macOS / Windows / Linux 三平台全部 P0 验收场景通过，导出打印不依赖本机 Office/WPS |
| G3 | 大规模学校的排课效率 | 在 8.2 定义的典型数据和测试条件下，熟练用户使用已整理好的 Excel 模板，从导入开始到完成自动排课 ≤ 2 小时；自动排课「正常」档 ≤ 5 分钟且该可行数据集全部应排课程进入课表、硬约束零违规。V17 按规定方法检验，未把未经测量的数字写成原软件实测结果 |
| G4 | 跨学段学校单文件可用 | 双学段不同作息 + 跨学段教师场景下，自动排课与手工调课全程零时钟冲突（V5 验收） |

### 1.4 非目标（不做）

1. 不做 Web 端、移动端。
2. 不做多用户登录、账号体系、在线协同、云同步——纯本地单用户。
3. 不做监考安排功能（业务方确认暂不考虑；逆向分析中原软件监考能力 DFM-REQ-037~043 暂不纳入范围）。
4. 不做从水晶排课 `.yqd/.dat` 私有格式的数据迁移。
5. 不支持半节课（同一节课两科各上半节）。单双周配对（单周上 A 双周上 B）**支持**，与半节课是不同概念。
6. 不承诺排课结果全局最优；课集采用启发式求解，允许「部分课程进暂放区待人工处理」。
7. 不做课表发布到教师/家长端的通知渠道（短信、公众号等），通知仅以导出文件方式交付。
8. 不采集任何遥测、崩溃报告、使用报告（含可选项）。
9. 不做大周（12/14 天周期）与 1~31 天短周期课表（业务方确认暂不考虑）。

### 1.5 调研输入（2026-10-12，公开产品页）

- 同类软件（jPK 精良排课、51 排课等）普遍将以下能力作为卖点：九年一贯制/跨学段、早读/晚自习/补课等课程类型、单双周与隔周安排、跨年级跨科目跨校区、按天/大周周期作息、教师细粒度时间约束。课集在跨平台 + 现代体验上差异化，功能上以上述通用能力为及格线。
- 晚自习/自习课管理在中小学的常见形态：**值班表**（星期 × 班级/楼层 × 看班教师），伴随调换班、次数统计、Excel 导出（WPS 智能表格方案、唯享科技方案等）。考勤点名类需求（学生签到）属独立系统，不在本产品范围。

## 二、用户与场景

### 2.1 角色

| 角色 | 描述 | 与系统的关系 |
|---|---|---|
| 排课员/教务员（主用户） | 学校教务处或指定排课老师，全校唯一数据维护者（单用户） | 全功能的操作者：录入、排课、调课、值班排班、导出、备份 |
| 任课教师 | 不直接操作软件 | 课表、调课通知、值班表的接收对象（通过导出文件） |
| 校领导/年级组长 | 偶尔查看课表与统计结果 | 只读查看（导出的总课表、工作量统计表） |

### 2.2 核心场景

| # | 场景 | 谁，在什么情况下，要完成什么 |
|---|---|---|
| S1 新学期从零排课（含一贯制） | 教务员，开学前 1~2 周 | 九年一贯制学校：建小学/初中两个学段（作息不同），录入班级、课时、科目节数、任课（部分教师跨学段），按学段自动排课，微调后导出打印各班课表 |
| S2 从旧课表迁移 | 教务员，换学期 | 拿上学期的 Excel 总课表反导入，自动重建科目/教师/任课/课表，补填简称后直接微调 |
| S3 学期中临时调代 | 教务员，学期中某老师请假 | 基于原始课表建调代课任务，查询该时段空闲教师，安排代课，设期限，导出调课通知 |
| S4 期末工作量结算 | 教务员，学期末 | 选统计期限，导出每位教师的应上/实上/调代节数（含权重，含跨学段合计）Excel 表 |
| S5 晚自习值班安排 | 教务员，开学初/每月 | 学校周五无晚自习、周日返校有晚自习；按天设好作息后，为各晚自习时段安排看班教师，自动分配+手工调整，导出值班表 |
| S6 换电脑 | 教务员，办公室换机 | 备份数据文件到新电脑，打开继续用（授权一机一码，新设备需另购激活码，见 US-041） |

## 四、需求详述

> 用户故事统一格式：`US-编号 作为<角色>，我希望<能力>，以便<价值>`。每条附验收标准（AC），验收标准全部可测。优先级标注 P0/P1/P2。

### M1 基础资料管理

**US-001（P0）学段管理** [新决策·D11]
作为教务员，我希望把年级划分到不同学段（如小学部、初中部），每个学段有独立作息，以便九年一贯制学校用一套数据排全校课表。
验收标准：
1. 学段为自定义集合，预置「小学部/初中部/高中部」可改名，支持新增（如「国际部」）；学段数量 ≥ 1。
2. 每个年级归属且仅归属一个学段；新建年级时必须选择学段。
3. 学段级独立配置：上课日、每日各时段类型节数（含按天覆盖，US-003）、节次起止时间、公共时段。
4. 单学段学校（绝大多数场景）默认仅一个学段，操作路径与单学段软件一致，不额外增加步骤。
5. 班级、科目、教师全校共享（不按学段隔离）；科目节数按年级录入（现状模型不变）。
6. 免任课与预设的「范围」选择器在全校/年级/班级之外增加「本学段」。

**US-002（P0）年级与班级管理** [逆向 DFM-REQ-001][官方 1]
作为教务员，我希望先建年级组再往里加班级，并可批量填充名称，以便快速搭起全校数据骨架。
验收标准：
1. 新增年级组时一次指定年级数量（并选学段）；新增班级时先选所属年级再指定数量。
2. 支持从常见名称模板批量填充年级名/班级名，支持撤销最近一次批量填充。
3. 修改年级/班级**名称**不影响其下已有数据（任课、课表等）。
4. 删除班级或年级时弹出二次确认，明确提示「该对象的科目节数、任课、课表数据将一并删除」。
5. 支持调整学段内年级顺序、班级顺序；总课表中年级按学段分组排列。

**US-003（P0）作息结构：上课日、节数与按天差异** [逆向 DFM-REQ-002 扩展][新决策·D12]
作为教务员，我希望设置学段默认作息（上课日 + 各时段节数），并可按天覆盖（如周五无晚自习、周日有晚自习），以便应对寄宿制学校的实际作息。
验收标准：
1. 上课日支持星期一至星期日任意勾选组合（学段级），默认周一至周五；周日上课场景（返校晚自习）可直接勾选。
2. 各时段类型节数学段级默认设置；**支持按天覆盖**：单独调整某一天的某时段节数（如周五晚上=0、周日晚上=2）。界面以「周视图网格 + 差异高亮」呈现哪些天与默认不同。
3. 时段类型见 US-006；每时段类型每天上限 9 节。
4. 提供课表格子可视化地图：按天 × 时段类型着色（各时段类型不同色 + 免任课红色），按天差异直接可见。
5. 容量按班级和实际周次分别计算：**某周可排节数 = Σ(该周各上课天、各时段可用节数) − 该周免任课格数**；覆盖为 0 的格子不计入。每周课分别占单周和双周的一个格，单双周课只占其出现周次；不得仅以两周总量代替单、双周各自的容量校验（US-013）。
6. 修改作息导致原课/免任课位置越界时，先列出将清除的设置和将进入暂放区的课节；用户确认后执行。若受影响课节属于已锁班级或教师，须先解锁才允许提交结构改动（US-023 AC5）。

**US-004（P0）免任课设置** [逆向 DFM-REQ-003][官方 2]
作为教务员，我希望按范围（全校/学段/年级/班级）把某些格子设为不排课，并能指定打印文字，以便处理班会、教研等固定安排。
验收标准：
1. 免任课范围可选全校、本学段、某年级、某班级，设置前必须先选定范围；默认全校。
2. 点击格子可设/取消免任课，右键可选类型。
3. 预置类型：无课、自习、劳动、教研活动、党团活动，支持自定义文字。
4. 设为「无课」时打印输出为空白；设为其他名称（含「自习」）时打印输出该名称，但该位置始终不排正课。
5. 免任课矩阵支持按天差异（与 US-003 的按天网格一致）。

**US-013（P0）单双周课程与配对** [新决策·D6][调研：51 排课「隔周安排」、jPK「单双周搭配上课」]
作为教务员，我希望科目节数可标记单周/双周，并允许两门课单双周共用同一时段，以便安排隔周课程（如音乐单周、美术双周）。
验收标准：
1. 科目节数支持三种周模式：每周（默认）/ 单周 / 双周。录入数字表示该课在**一个实际出现周**要上的节数，而非两周累计数。同一班同一科目可拆成多条需求，如“每周 3 节 + 单周 1 节”；教师分配和强制连堂可分别关联到需求行。同班同科的科目预设统一作用于这些需求行的实际出现周，不按周模式另设一份（D14）。
2. 单双周配对：可将同班两门课（一单一双）绑定到同一时段，界面提示配对结果（如「音乐(单) ↔ 美术(双)」）；配对可解除。
3. 容量必须按周次分别校验：`每周课节数 + 单周课节数 ≤ 单周可用格数`，`每周课节数 + 双周课节数 ≤ 双周可用格数`。只有两项均成立才算通过；两周合计与周平均仅供展示。反例：每周仅 1 格、录入 2 节单周课时，两周总量虽为 2，单周仍应报超载。
4. 排课以两周为周期求解：同一班级同一时段，单周课与双周课可各排一门；同一教师同一时段的两门课若周次不重叠（一单一双），**不算冲突**。
5. 全局规则（US-018）与自定义条件（US-017）在单双周课上的执行口径：按「该课实际出现的周次」判定（如「每天最多 1 节」只约束该课实际出现的天）。
6. 调代课、工作量统计按教学日历映射到自然日期后的实际出现次数计；学期起始教学周定义为单周，此后单双周交替。未设置教学日历时仅能展示周模板或周平均，不得输出宣称为实际日期统计的数字（US-029/031）。
7. 预设（US-015）与自定义条件的配置不区分周次，对单双周共用同一规则定义（D14）；实际校验只在课程出现的周次执行（AC5）。

2. 同级同科进度一致：尽量一致（默认）/ 即使冲突也一致（硬性）。判定口径为同一实际周、同一年级同科且该周需求节数相同的班级，截至每个上课日累计已上节数最大值与最小值之差 ≤ 1；选硬性档时不得违反该口径，可能因此有课排不下，界面须提示风险。
3. 教师当天课程分布：尽量分散到上下午 / 尽量集中在一个午别 / 无所谓（默认）。
4. 教师午休保护：可选「禁止教师上午末节与下午首节连续有课」（硬性）或「无所谓」（默认）。
5. 科目连堂规则（三选一）：尽量不连堂但可连 / 宁可不排也不连堂（硬性）/ 同一天的课尽量连在一起。
6. 已设置「两节连堂次数」的科目不受第 5 项管辖。
7. 所有规则项持久化，重开数据文件后保持。
8. 「检测进度一致」默认开启（D10）。

**US-021（P0）约束执行语义** [逆向 CODE-REQ-003/004/005 提供算法线索][新决策·v0.4]
作为教务员，我希望硬约束和软偏好有可检查的执行口径，以便理解排课结果。
验收标准：
1. **第一层为硬约束**：已排课表中的位置、占用、免任课、一定排/不排、上限、互斥、合班、强制连堂及硬性全局规则不得违规，不能以软偏好换取硬违规。最少/固定次数一类总量规则如因课程暂放而未达到，必须在结果报告列为“未满足的硬性需求”，不得宣称完整课表满足全部硬约束。无法安排的课程留在暂放区，并给出 US-019 AC4 的阻断清单。
2. **第二层为已排覆盖量**：在所有已排课节满足硬约束的前提下，尽量提高两周周期内已排的实际课节出现次数。**第三层为软偏好**：在覆盖量相同的候选结果中，比较四类偏好的满足率（各类满足实例数 ÷ 适用实例数），四类等权，最大化满足率之和；没有适用实例的类别不计分。结果报告给出覆盖量及每类偏好的分子、分母、满足率；不承诺全局最优或每项软偏好都满足。这是课集新定的评价口径，不是对原软件评分公式的断言。
3. 提供「固定随机种子」复现模式：同一平台上，相同的已提交数据版本、求解器版本、选课范围、强度档位和种子，应得到同一结果及报告；该模式使用固定候选检查预算和确定性执行顺序，不依赖运行时钟停止。报告保存上述复现参数。
4. 算法不承诺全局最优，文档与 UI 文案不得出现「最优课表」承诺性表述。
5. 强度档位只改变候选检查预算，不改变上述优先级；同一数据与固定种子下，高强度沿用低强度已找到的最好结果，不能降低覆盖量，覆盖量相同时不能降低上述软偏好满足率之和。具体预算属于技术方案并由 V17 校准，不把旧软件的连续未改善阈值直接当成课集参数。

软偏好实例的验收计数口径如下；“满足率之和”相同时按排课结果中稳定课程 ID、周次、学段、日与时段节次组成的规范序列比较，使复现模式的并列结果也可确定：

| 类别 | 一个适用实例 | 满足条件 |
|---|---|---|
| 尽量排 | 一次实际出现周的课程需求，且该需求设置了尽量排格 | 该需求排在其任一尽量排格 |
| 同级同科进度尽量一致 | 同一模板教学周、同一年级同科目的一组班级和一个上课日 | 截至该日，各班累计已上该科节数最大值与最小值之差 ≤ 1；该周节数需求不同的班级不参与同组比较 |
| 教师分散/集中 | 某位教师在一个模板上课日有 2 节及以上课程，且选择了该偏好 | 分散：上午、下午均有课；集中：只在一个午别有课。没有上午/下午可比较格的上课日不适用 |
| 非强制连堂偏好 | 某班某科在一个模板上课日有 2 节及以上课程，且受全局连堂偏好管辖 | “尽量不连”：没有相邻节；“尽量连在一起”：该日该科节次无中间空档 |

3. 已有正课、重复覆盖、越界节次和其他免任课标记应提示具体冲突。草稿可保存，正式占用随确认后的版本生效。

**US-033（P1）教师安排与临时替班**

1. 教务可手动指派，也可从参与教师池智能补齐。带班禁排、每周节次和天数上限、正课与带班时间冲突均为硬约束。智能补齐优先排满，随后均衡节次。

1. 班级、教师、学校课表及导出均显示生效的活动和老师。合班教师侧只记一次，连续两节计两节，带班负担单独展示。

**US-038（P0）数据文件管理** [逆向 DFM-REQ-051/052、CODE-REQ-009][官方 index]

## 五、流程与状态

### 5.1 主流程（编号步骤）

1. 新建/打开数据文件 → 2. 定义学段、设置班级（US-001/002/035）→ 3. 设置作息：上课日、时段类型与节数、按天差异、免任课、节次时间（US-003~006）→ 4. 科目节数 + 周模式 + 容量校验（US-012/013）→ 5. 教师任课（US-009）→（可选：场室、合班、预设、条件）→ 6. 开始自动排课：全校或按学段（US-019~021）→ 7. 课程表查看/手工调课/检测（US-022~024）→ 8. 保存、导出打印、调课通知（US-025/036）。
前四步之间允许回改；已排课表后的结构性改动（任课、合班、节数、免任课、作息）若使课节失去合法位置，先列出影响，用户确认后将相关课节移入暂放区；受锁保护的课节须先解锁（US-023 AC5），不得静默丢课（贯穿 US-003/009/010/012）。

### 5.2 一节课的状态机

「位置」的定义 = 学段作息的（天 × 时段 × 节次 × 周次），单双周课各占其中一个周次层。

| 当前状态 | 触发动作 | 目标状态 | 副作用 |
|---|---|---|---|
| 未排（科目有节数无位置） | 自动排课成功 / 手工放置 | 已排定 | 校验全部硬约束（含跨学段时钟、周次重叠）；写入课表 |
| 已排定 | 拖动到合法格 | 已排定（新位置） | 联动更新各视图；记录撤销快照；计入调课通知 |
| 已排定 | 合法的拖放至暂放区 / 已确认且无相关锁的结构改动 | 暂放 | 从正式课表各视图移除，暂放区可见；提示 |
| 暂放 | 手工拖回合法格 | 已排定 | 同上 |
| 已排定 | 锁定所属班级或授课教师 | 已排定（受锁保护，派生状态） | 只要任一相关班级或教师仍被锁定，拒绝手工调动；自动排课保留其位置 |
| 已排定（受锁保护） | 解除全部相关班级及教师锁 | 已排定 | 恢复可调动；锁属于班级/教师，不作为单节课独立状态持久化 |
| 任意 | 撤销 | 上一状态 | 会话内历史回退 |

### 5.3 调代课任务继承（P1）

原始课表为根；任务基于原始课表或父任务创建；父级改动传到子任务未覆盖的课节，引用失效则标为需修复；删除父任务时先固化子任务当前有效差异，再改挂到原始课表下。保存任务不写回原始课表；设期限、配置教学日历且无重叠/继承冲突时才计入工作量（US-027/029）。

### 5.4 数据文件生命周期

创建 → 完整提交的录入/编辑版本（可暂存、按节点生成镜像）→ 手工备份（复制安全副本）→ 恢复（先校验恢复前副本与目标备份 → 提交替换 → 失败回到副本）。进行中的排课、导入或恢复不能进入自动暂存或镜像。文件记录的移除不影响磁盘文件。

### 5.5 值班排班流程（P1）

定义作息并标明班级具体自习格 → 为这些格子定义值班需求（格子 × 班级 × 人数）→ 设教师次数/天数上限与软性规则 → 自动分配 → 缺口/冲突清单 → 手工修正 → 导出值班表；学期中临时换班记入独立统计。

## 六、边界与异常（逐项自查）

| 类别 | 问题 | 本期答案 |
|---|---|---|
| 空态 | 新数据文件、无任何班级时打开各界面 | 主界面仅主流程入口可用（US-040）；各录入界面显示空表格 + 引导文案；课表入口禁用 |
| 极值 | 节数拉满（每时段类型 9 节 × 多类型）、科目/教师数极大、课格文字超长 | 节数上限 9/时段类型/天（US-003）；规模上限见 8.2；课格文本溢出按导出设置的「缩小/换行」处理（US-036），界面内省略号 + 悬停全文 |
| 跨学段 | 学段作息差异极大（如小学 6 节/天、初中 12 节/天）；学段时间未填或排好课后改时间 | 涉及跨学段教师、合班或共享场室的操作在时间未填全时阻止；时间改动产生新冲突时列出受影响课节，取消改动或确认移入暂放区（US-005/010/014/020） |
| 单双周 | 单周课与双周课同格；教师一单一双同格；单周需求独自超容量 | 同格不同周次不冲突；容量分别按单、双周校验，不能用两周总量掩盖单侧超载；无双周课时对应视图显示空态提示（US-013/023） |
| 并发 | 同一数据文件被两个实例同时打开 | 文件级锁：第二个实例提示「文件已在使用」并拒绝打开（单机单写者） |
| 失败 | 排课中取消/崩溃；导入中途失败；恢复失败；磁盘满 | 排课/导入/恢复的中间状态不进入已提交文件或自动暂存（US-019/035/039）；恢复失败保留恢复前副本（US-038）；保存失败保留内存中尚未提交的编辑并提示另存，重启只能恢复最后完整提交或完整暂存版本 |
| 权限 | 误操作 | 结构性删除（学段/年级/班级/科目/教师/时段类型）一律二次确认并列出将被连带删除的数据（US-001/002/006/007/008）；恢复与反导入前置备份提示（US-037/038） |
| 幂等 | 重复导入同一模板；重复执行自动排课 | 导入两段式 + 差异预览，重复执行显示「将新增 N 条 / 已存在跳过」；自动排课可重复执行，锁定课节保留（US-019 AC5） |
| 输入校验 | 节数为负/非数字、简称重复、同名教师、时间格式 | 节数仅接受非负整数；简称重复允许但列出警告；同名教师必须可区分（US-008 AC5）；时间格式校验（US-005 AC4） |
| 约束矛盾 | 一定排与不排同时命中同格等硬冲突 | 保存预设时警告（US-015 AC6）；排课时相关需求进入暂放区，报告列出候选格实际触发的阻断条件，不宣称唯一或最小冲突原因（US-019/021） |
| 自习值班 | 免任课「自习」、晚自习时段和已排正课交错 | 只对班级具体自习格建立值班需求；已排正课的格子拒绝值班需求，时段类型本身不自动产生需求（US-004/032） |

## 八、非功能需求

### 8.1 平台与兼容（硬约束）

1. 支持 macOS（含 Apple Silicon）、Windows 10+、Linux 主流发行版三平台，同一套功能与验收标准。
2. 离线可用：全部核心功能（录入、排课、调课、值班、导出、打印、备份）不依赖网络；激活后授权验证也不依赖网络。
3. 导出/打印不依赖本机 Office/WPS 安装。
4. 快捷键遵循平台惯例（macOS 用 Cmd）。
5. 中文为一等语言；高分辨率屏幕正常渲染。

### 8.2 性能与规模（产品目标及发布验收方法）

| 项 | 目标 |
|---|---|
| 规模假设（典型校，含一贯制大学校） | ≤ 4 个学段、≤ 24 个年级、≤ 400 个班、≤ 800 名教师、≤ 80 个科目、每周 ≤ 7 天、每天每时段类型 ≤ 9 节、两周周期 |
| 规模上限（不崩溃，允许降速） | 典型规模的 1.5 倍（约 600 班 / 1200 教师） |
| 自动排课（正常档，典型规模，全校一次排） | ≤ 5 分钟；快速档 ≤ 2 分钟 |
| 课表视图切换 / 拖动响应 | < 200ms |
| 数据文件打开/保存（典型规模） | < 3 秒 |

性能测试使用三平台各一台记录型号与 OS 版本的发布参考机（至少 8 逻辑核 CPU、16 GB 内存、SSD），首次发布前固定机器清单；在同一台机器上完成三次冷启动测量，记录各次耗时，三次均须符合上表。界面响应从用户操作事件到可继续交互的结果帧计算，打开/保存从发起到完整提交并可重开计算；自动排课从点击开始到结果报告可用、数据提交完成计算。不得通过省略保存或报告缩短计时。

V17 的典型数据集须由固定版本生成器、固定种子和公开在项目内的清单生成，覆盖 400 班、800 教师、80 科目、跨学段/单双周/按天作息/场室/合班及五类条件；生成时保留一份已知可行的排课解。时间目标只在这份可行数据集**全部应排课节已排定且硬违规为零**时视为通过。600 班/1200 教师的上限数据集单测“不崩溃”，允许降速，但必须可保存、重开并完成检测。零录入到排课的 2 小时目标另由 V18 测试：提供事先整理好的导入表，不把整理学校原始资料的时间混入软件操作耗时。

### 8.3 可靠性

1. 任一保存、导入或恢复操作被进程终止、断电或磁盘满打断后，重开时必须能读取最近一次完整提交的数据，或明确提供经校验的恢复前副本；不得把半写文件误认作有效数据。具体落盘和同步策略在技术方案中规定，并用故障注入验收。
2. 自动暂存 + 自动备份镜像 + 恢复前副本三层保护（US-038/039）；三者均不得保存进行中的求解或导入中间状态。
3. 撤销/重做会话内 ≥ 100 步。

### 8.4 安全

1. 数据文件为本机明文业务数据；不宣称加密，不使用文件头混淆冒充安全。
2. 不上传任何学校数据（除用户主动导出文件）；无遥测通道。
3. 授权激活信息与本机数据文件分离存储，丢失数据文件不影响授权。

## 十、待确认问题状态

v0.1/v0.2 的业务选项已按 D1~D19 收录；本次 v0.4 在不改变这些决策及现有 P0 范围的前提下，为原文未定义或互相冲突的语义给出了可实施口径。新增口径包括单双周各侧容量、学期日历、时间改动处理、自习值班、软偏好评价、任务继承冲突、锁定粒度和设备重装。**这些 v0.4 口径需要业务方复核后，才可将状态改回“需求基线已确认”。**
